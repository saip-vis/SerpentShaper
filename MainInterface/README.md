# SerpentShaper: connected experimental interface

Open `MainInterface/index.html` locally. Choose **Create a new snake** or one of 149 source species. Choosing a species loads one reported venom profile (the lowest source-row number) into the editable controls and displays the species' authored reference illustration separately. Species can have multiple profiles and variation; the selected row is not an average. Missing and disputed values remain blank. The dropdown is a starting point, not a lock: changing the venom drives the generated concept, and the same venom values produce the same concept regardless of the selected reference. Entering a nonzero amount produces a concept; blanks and zeros are inactive for inference but remain distinguishable in the exported SVG metadata. A single entered component is allowed, with a sparse-input warning. New edits cannot take the entered total above 100%; values are never redistributed. If a source profile itself exceeds 100%, its reported values are shown unchanged, flagged for review, and generation is disabled until the total is reduced. The display is an imagined snake, not a species identification or evidence that venom determines anatomy.

For study uploads, run `./start_serpentshaper.sh` from the repository root and open the `http://127.0.0.1:8768/` address it prints. The server requires Python and `pypdf` (`python3 -m pip install pypdf` if needed). Directly opening the HTML still runs the existing illustration interface, but the study controls require this local server.

The **Explore an uploaded study** section accepts up to five PDFs or UTF-8 text files, 12 MB each. It extracts text locally, searches passages by keyword, and displays the file name and page number. Limited literal matches such as `PLA2: 24.5%` can be applied to the existing venom inputs only when the user clicks them; the 100% limit still applies and other values are not redistributed. The quoted text is not proof that a value is a venom abundance for the desired sample: verify its context and whether categories overlap. Tables and scanned PDFs may be extracted incorrectly or not at all, and no OCR is provided. Uploaded text is held in the local server's memory, cleared when the server stops or the user chooses **Clear studies**, and is not sent to an external AI provider.

Applied study values and their file/page references remain visible while those inputs are unchanged. Their attribution is held in the current browser session only; it is cleared when a value changes, a starting species is selected, or studies are cleared, and is not embedded in the downloaded SVG.

**Ask local AI** is an optional retrieval-augmented answer: the server retrieves passages by keyword and sends them only to `llama3:latest` on a locally running Ollama service at `127.0.0.1:11434`. It requires Ollama and that model to be installed separately. The answer is displayed with the cited source passages; check them yourself, since a valid-looking citation does not prove a claim is supported. The model cannot change the venom inputs; only the explicit literal-source buttons do so. It does not retrain the phenotype model. Local proxy use and redirects are disabled for model requests, and document text is treated as untrusted data.

Each input includes an expandable explanation of its source category and its boundaries. The twelve inputs are broad toxin-family or peptide categories, not individual compounds or verified measurements of their physiological effects.

`connected-model.js` is a **direct experimental hybrid model**: a continuous RBF kernel ridge maps venom inputs to shared SVG design controls; inference does not select or rank a species. It was trained on 275 proteomic profiles joined by source label to 148 hand-authored snake designs. Its anatomy, hood, tail and motifs therefore reflect those designs, not measurements learned from photos. The model's patch-color regressions use nine body patches from eight source labels and contribute 15% of the displayed skin color. A patch may contain markings or lighting effects and is not the whole-animal color. Venom and photos are not known to come from the same individual. Image-derived shape training remains a separate unfinished project, documented in `../ML/learned_morphology/README.md`.

The generated concept uses the project's detailed renderer, including individual scales, shaded head detail, a curved body, a continuous hood and tail, and mixed band, diamond and blotch patterns. Its shared pose and interpolated anatomy are built from two authored geometry templates; the chosen starting species is not used to select those templates. Learned shape and motif controls vary continuously, while individual scale sampling and rendered colors are discretized. Marking and scale spacing are learned from authored settings, then mapped into renderer units; they are not anatomical measurements. Generalized motifs do not reproduce every natural pattern, and the shared pose does not reconstruct every species' posture. Dorsal and ventral use the same shape; ventral plates and color are illustrative and are not derived from a matched underside photograph. The selected species reference uses its original separate preset. The earlier reference-blending experiment also remains available in the [research interface](research-interface.html), whose [notes](README-research.md) describe its different method and limitations.

The explanation list compares each entered component with setting that component to zero and reports the largest change in the model's shape controls. This is an exact description of the model's calculation, not a causal biological explanation or a confidence score. Shape inputs ramp over two percentage points near zero and downweight missingness; the separate photo-color component retains its one-point ramp. Returning a component to zero restores the same generated appearance as leaving it blank. Smoother changes do not guarantee a biologically accurate prediction. The model can still extrapolate poorly, especially for unusual or sparse profiles.

The generated renderer also supports continuously varying tail flattening and pale band accents, learned from categories in the authored designs. These are approximate visual features, not measured morphology: for example, the model assigns some flattening to a cobra profile and does not reliably produce the yellow-bellied sea snake's coloration. The [visual checks](../reports/visual_generation_checks/README.md) show these limitations and compare examples before and after the smoothing change.

For generated concepts, a strong combined band-and-band-accent cue now carries an illustrative version of the band colors onto ventral plates. It fades continuously with both cues and does not alter species reference presets. This is an authored-pattern-inspired visualization, not evidence that the venom specifies an underside or that the pictured individual has those markings.

Generated concepts also use a smooth visual-emphasis curve for diamond motifs and rattles, making moderate learned cues easier to see and very small rattle cues invisible. This presentation choice does not change the model's toxin inputs or make the displayed markings or appendage a biological prediction. Authored species reference presets keep their original appearance.

Under the illustration, **Compare real-snake venom profiles** ranks real dataset rows by the entered percentages, independently of the generation model. It considers all entered finite values, including explicit zero; blank inputs are ignored. For each source row, the adjusted distance is the sum of absolute differences across shared categories plus a fixed **25 percentage-point ranking penalty** for each missing or uncertain source category, divided by the number of entered categories. It requires at least one shared category and shows the best row per species. Lower is closer; ties prefer more shared categories, then a smaller average difference on shared categories. The penalty is an engineering choice, not a measured or imputed concentration or a biological probability; another penalty can change the ranking. Similarity is especially weak with few entered or reported categories, and unentered categories (including ones present in the source) do not affect it. Explicit zero and blank therefore differ here even though both are inactive for generation. The matching list does not control the generated snake.

**About your snake** presents contextual species references for the closest ranked profile only when it has at least three shared categories, at least 60% coverage of entered categories and an adjusted difference of at most 20 points. These are engineering gates, not scientifically validated confidence thresholds. Habitat, microhabitat, broad diet and maximum total length come from the cited ReptTraits compilation; the example prey is one naturally observed feeding record from Squamatabase with its original citation. These are observations for a named real species, not estimates or measurements of the invented animal, and the reported maximum length is not a typical size. When the reference is too sparse or a field is missing, the interface says so. The reference bundle is reproducible with `python3 scripts/build_species_context.py` (requires `openpyxl`) and joins only exact species labels; synonyms and unreviewed matches are excluded.

The **reference LD50 range** is the minimum to maximum published point estimates for at least two qualifying species among the top five venom matches. These limited values are curated from [Sánchez et al. 2003](https://pubmed.ncbi.nlm.nih.gov/12565759/), [Leong et al. 2012](https://doi.org/10.1371/journal.pntd.0001672.t001), and [Araya et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11004356/). A result uses measurements from one study at a time, all mouse intravenous in mg/kg; the study covering the most of the top five species is chosen, with the newest breaking ties. Mouse strain, time window and venom samples still differ between studies. For the historical `Crotalus viridis oreganus` label in Sánchez, the match to `Crotalus oreganus` is explicit and should be taxonomically reviewed. Regional Naja measurements are shown separately. No eligible study with two species means no range. The range is not a prediction interval, not validated for invented snakes, not a human toxicity estimate, and does not establish a venom–lethality relationship; the study venoms are not the samples used for the matched venom profiles. The 25-point missingness penalty, the top-five limit, and the match gates can all affect which references appear. Source set is small and geographically biased.

Each card identifies the source row, comparison coverage, average difference on reported categories, missing categories and source subtotal for the 12 displayed categories. That subtotal may not represent the full sample; source rows come from the dataset, not necessarily the model's training set. The DOI links to the source dataset, not a verified primary paper for each row.

For species with reviewed photo observations, the source card also offers a link, attribution and a note describing the visible body region. These are contextual references and do not calculate venom comparisons. Photo species labels are community identifications rather than independently expert-verified identifications. Rebuild the link bundle with `python3 scripts/build_reviewed_photo_evidence.py`; this requires the local reviewed images and the photo-pilot dependencies.

While a slider is moving, the drawing updates and the previous comparison list is labeled as pending. Releasing the slider refreshes the list automatically; typed values refresh it as they change. **View photo references for color** separately lists the nine credited photos used by the color model and does not assign per-photo influence. The checked-in model contains links and attribution, not the source images. Individual snake photographs are not known to be matched to the venom measurements.

Training is documented in [connected_prototype.json](../ML/learned_morphology/connected_prototype.json): it includes held-out-genus errors for the authored design controls and comparisons to a simple mean baseline. The grouped folds were examined while selecting the kernel and are not an untouched final test. The color pilot's average channel error was about 35.3/255 versus 33.2/255 for the baseline on its very small held-out test. These results are evaluations against design labels or small patches, not evidence of scientific or image-generation accuracy.

## Rebuild and test

Rebuilding the model requires Python with NumPy and scikit-learn and the original local accepted photos. Images remain excluded from Git; `train_connected_prototype.py` checks their recorded hashes and review states. Pillow is needed only for re-extracting patch measurements. See the learned morphology notes for acquisition and licensing caveats.

```sh
python3 scripts/train_connected_prototype.py
node --test MainInterface/connected-inference.test.cjs
node --test MainInterface/detailed-concept.test.cjs
python3 -m unittest discover -s tests -p 'test_connected_prototype.py'
```

The model is bundled for local browser inference; no external service or user-data upload is involved. Do not treat the checked-in SVG renderer or the model's generalized patterns as a scientific reconstruction.
