# SerpentShaper venom explorer

Open `MainInterface/index.html` in a browser. The interface is local and uses the checked-in data bundle and the existing procedural SVG renderer; no server or packages are required. Select a measured proteomic profile or clear it to enter a composition. Expand **More families & peptides** for additional source categories. Values are session-only.

Each blank control means unknown or unreported, while an entered zero remains explicitly visible and is preserved in exported input metadata. In this interface, both blank and 0% are **inactive for generation**: they do not contribute to reference matching or count toward the three-component minimum, and the style model handles them using its missing-value path. This is a deliberate interaction rule, not a claim that a zero measurement and an unknown measurement are scientifically identical. A reported zero in a reference remains a valid value when a positive user input is compared to it. Selecting a measured profile retains other source categories, including missing values. The reported total includes editable values and other reported source categories; the unallocated amount is only an arithmetic balance. Totals are not automatically normalized, and historical source totals can differ slightly from 100%. Family categories are kept distinct and no parent-child aggregation is inferred. The peptide controls are broad source categories, not individual peptide identities.

An uncertain black mamba NP source value is deliberately left blank and excluded from similarity comparisons. Its original value remains in the database and generated component metadata; the [quality flag](../config/venom_quality_flags.json) records why it is withheld. A user may enter their own NP value, but the withheld reference value will not be used for matching.

The reference list compares only the active (above 0%) editable categories reported in both the input and each dataset profile. At least three active categories must be shared with a reference. Its descriptive similarity score is `(shared categories / active categories)^3 * exp(-mean absolute difference / 2)`. The highest-scoring profile per source species label contributes, and scores are normalized across all eligible species labels. The five strongest are shown with comparison details, and the rest are combined in the display; all their weights are used in the rendering. The formula's coverage exponent and distance scale are engineering choices, not values learned or validated from biological data. The displayed percentages are relative blend weights, **not** genetic ancestry, predicted species, or biological confidence. The full set of weights influences style; anatomy only combines compatible reference shapes. Comparisons with few shared categories are weak, and the same score can describe very different unknown compositions. Source names are joined to illustrations by exact label, not verified taxonomic identity. Held profiles and transcriptomic measurements are excluded. The source DOI is dataset-level; it is not a per-profile primary study citation.

When the set of active categories stays fixed, small changes in a percentage change the underlying reference scores continuously. A best matching source row can change, but a hard top-three cutoff no longer makes entire species enter and leave the blend. Turning a component on or returning it to zero changes the set of comparable evidence and can change weights abruptly. Separate discrete renderer choices (notably cobra versus other body forms, pattern and tail) can still change suddenly even with smoothly changing weights. The numerical weights do not establish that venom determines the visual characteristics.

The interface starts with a blank composition. With at least three active, comparable categories, it selects a broad body form by total reference weight and blends compatible hood widths or body stations and head geometry. Viper and terrestrial presets share a projection, so their body geometry and compatible head shapes can blend across the category boundary. Pattern and tail types are still chosen from weighted categories. Cobra and other body forms currently use different projections and cannot yet be smoothly blended: a cobra-to-viper transition can still switch abruptly. The output is labeled a hypothetical concept rather than an identified species. The blended shapes are an illustrative reference-based hypothesis, not a scientifically validated phenotype inference.

For visual style, the system averages the experimental regression's outputs with the weighted reference-style blend, then mixes that result with the authored pattern reference. It adjusts skin and marking colors, marking spacing, scale detail and a small width factor. The model is trained on the project's authored artistic presets paired by source species label, not on photographs or individual venom samples. Its results are imagined concepts, not validated biological predictions. The model uses training-set median imputation with explicit missingness indicators; a blank input is not a claim that a toxin is absent. Download SVG saves the displayed concept, while **Explore reference anatomy** opens the separate preset editor; it does not transfer the generated concept. Dorsal and ventral controls alter the displayed surface of the existing single-projection SVG; they are not reconstructed angles. Study uploads, RAG, individual peptides and ecological inference are not implemented.

One small reference-only photo cue is available for *Crotalus atrox*: two manually selected patches of diamondback body scales supply approximate dark and light colors. When that reference contributes to a compatible diamond-pattern concept, the renderer blends the colors into the dorsal diamond center and border at up to 20%, scaled by its reference weight. The actual input and strength depend on the current blend. Other patterns, species and the ventral view are unchanged. The evidence panel links the source photographs, and the downloaded SVG records attribution and cue strength. Color varies with lighting, individuals and sample selection; this is an illustrative, limited reference, not photo-based training or a reliable color estimate for the species. The local original photos are not sent to the browser.

## Rebuild and verify

From the repository root (the training and Python test commands require NumPy and scikit-learn):

```sh
python3 scripts/build_species_presets.py
python3 scripts/build_main_interface_data.py
python3 scripts/train_visual_style_model.py
python3 scripts/build_photo_cues.py  # requires the original local photographs, Pillow and NumPy
node --test MainInterface/matching.test.cjs MainInterface/style-inference.test.cjs MainInterface/style-library.test.cjs
python3 -m unittest discover -s tests -p 'test_visual_style_model.py'
```

The data builder reads the cleaned SQLite database and checks the toxin-control source binding. It writes `venom-data.js` with 276 eligible proteomic profiles and all source categories. The visual style trainer writes an inference bundle and [training manifest](../ML/visual_style_model.json) with hashes, source labels, input values, artistic target parameters and limitations. Dataset counts may change when inputs change. The tests check training-to-browser numerical parity, quality exclusions, bounded style and width changes, closed contours, comparisons and controller interactions.
